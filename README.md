# 531 TRAIN v6

스마트폰에서 사용하는 5/3/1·3/5/1 훈련 기록 앱입니다. GitHub Pages에 올려 사용하는 정적 웹 앱(PWA)이며, 기록은 현재 기기의 브라우저에 저장됩니다.

## 훈련 구성

프로그램은 **5/3/1 또는 3/5/1** 중 하나를 선택합니다. 요일 없이 **스쿼트 → 벤치프레스 → 데드리프트 → OHP**를 진행합니다. 네 종목의 운동 완료를 기록하면 다음 주차로 넘어갑니다. 컨디셔닝은 앱 밖에서 별도로 진행합니다.

| 주차 | 5/3/1 | 3/5/1 |
| --- | --- | --- |
| 1주차 | 65% × 5, 75% × 5, 85% × 5+ | 70% × 3, 80% × 3, 90% × 3+ |
| 2주차 | 70% × 3, 80% × 3, 90% × 3+ | 65% × 5, 75% × 5, 85% × 5 |
| 3주차 | 75% × 5, 85% × 3, 95% × 1+ | 75% × 5, 85% × 3, 95% × 1+ |
| 4주차 · 선택 | 40% × 5, 50% × 5, 60% × 5 | 40% × 5, 50% × 5, 60% × 5 |

비율의 기준은 TM입니다. `+`는 마지막 세트의 PR 반복 기록을 뜻합니다. **3/5/1의 2주차는 5회 고정이며 PR과 조커가 없습니다.** 4주차 디로드도 PR과 조커가 없습니다. 기본 설정은 3주 훈련 후 4주차 디로드이며, 디로드를 끄면 3주 후 다음 사이클로 진행합니다.

### 보조운동 1

**생략 / 조커 1세트 / 조커 2세트 / 조커 3세트 / FSL** 중 하나를 선택합니다. 조커와 FSL을 동시에 수행하는 구성은 아닙니다.

| 선택 | 수행 방법 | 세트 간 휴식 |
| --- | --- | --- |
| 조커 | 각 세트 1회, 최대 3세트 | 3분 |
| FSL · 벤치/OHP | 첫 메인세트 중량으로 5세트 × 8회 | 3분 |
| FSL · 스쿼트/데드 | 첫 메인세트 중량으로 5세트 × 4회 | 3분 |
| 생략 | 추가 바벨 운동 없음 | — |

조커는 **PR 세트의 TM 비율에 세트마다 7.5%포인트씩 더합니다.** 계산식은 `TM × (PR 비율 + 0.075 × 조커 세트 번호)`입니다.

| 마지막 메인세트 | 조커 1 | 조커 2 | 조커 3 |
| --- | --- | --- | --- |
| TM 85% | TM 92.5% | TM 100% | TM 107.5% |
| TM 90% | TM 97.5% | TM 105% | TM 112.5% |
| TM 95% | TM 102.5% | TM 110% | TM 117.5% |

각 세트를 원래 TM에서 계산하며, 앞 세트의 반올림 중량에 다시 비율을 곱하지 않습니다. 앱은 TM 비율과 계산 중량을 표시하고, 실제 사용할 중량은 **가장 가까운 2.5kg 단위**로 반올림합니다. 정확히 중간값이면 높은 쪽으로 반올림합니다.

이 조커 증가폭과 FSL 반복수는 사용자가 지정한 맞춤 규칙입니다. FSL은 PR 없는 주차에도 선택할 수 있습니다.

### 보조운동 2 · 풀업

- 세트 수 제한 없이 실제 수행한 반복수를 추가합니다.
- 세트 간 휴식은 **1분**입니다.
- 목표는 **한 주의 네 종목 훈련에 걸친 합계**입니다. 예를 들어 목표가 20회라면 네 번의 훈련에서 기록한 풀업을 합쳐 20회를 채웁니다.
- 1·2·3·4주차 목표는 각각 직접 입력합니다. 초기 목표는 미설정이며, 임의의 목표 횟수를 처방하지 않습니다.
- 풀업 목표 달성 여부는 메인 훈련 완료나 다음 주차 이동을 막지 않습니다.

## 워밍업과 타이머

바벨 워밍업 중량을 자동 표시합니다. 기본 비율은 TM 40%·50%·60%이며, 빈 봉 워밍업은 해당 종목에 함께 표시합니다.

| 구분 | 휴식 타이머 |
| --- | --- |
| 워밍업 | 1분 |
| 메인세트 | 3분 |
| 조커·FSL | 3분 |
| 풀업 | 1분 |

총 운동 시간은 시작·일시정지로 기록합니다. 휴식 타이머와 별도의 타바타 타이머도 사용할 수 있습니다. 앱에 돌아오면 저장된 시각을 기준으로 경과 시간과 남은 시간을 계산합니다. 화면 잠금이나 백그라운드 상태에서는 기기·브라우저가 실행을 제한할 수 있으므로, **정확한 시점의 소리·진동 알림을 보장하지 않습니다.**

## TM과 이전 기록

기존 브라우저에 저장된 TM과 운동 이력은 유지합니다. 기존 프로그램이 1000% Awesome이면 이력은 보존하고 새 3/5/1 진행을 시작합니다. 이전 조합을 새 프로그램의 완료 기록으로 자동 간주하지 않습니다.

새로 설치한 기기의 기본 TM은 다음과 같습니다. 기존 저장값이 있으면 그 값을 우선합니다.

| 종목 | 새 설치 기본 TM |
| --- | --- |
| 스쿼트 | 127.5kg |
| 벤치프레스 | 82.5kg |
| 데드리프트 | 135kg |
| OHP | 52.5kg |

TM은 설정에서 변경할 수 있습니다. OHP를 포함해 이전에 직접 저장한 TM을 업데이트 과정에서 기본값으로 덮어쓰지 않습니다.

## GitHub Pages 업데이트

1. 기존 앱의 설정에서 **JSON 백업**을 내려받습니다.
2. 업데이트 ZIP을 압축 해제합니다.
3. 기존 저장소 `https://github.com/catcatmatch/531-`의 같은 게시 위치에 파일을 업로드하고 같은 이름의 파일을 교체합니다. ZIP 파일 자체가 아니라 **압축을 푼 내용물**을 올립니다.
4. 새 파일인 **model.js**도 반드시 포함합니다. `index.html`, `app.js`, `logic.js`, `model.js`, `style.css`, `sw.js`, `manifest.webmanifest`와 `icons` 폴더가 같은 앱 경로에 있어야 합니다.
5. 변경 사항을 커밋하고 GitHub Pages의 게시가 끝나면 기존 앱 주소를 다시 엽니다. 이전 화면이 보이면 앱을 닫았다가 다시 열거나 새로고침합니다.

기존 파일과 동일한 위치에 올려야 합니다. 파일들을 한 단계 더 깊은 폴더에 넣으면 앱 주소가 달라질 수 있습니다. 이 패키지를 내려받는 것만으로 GitHub에 배포되지는 않습니다.

기존 **주소와 브라우저**를 계속 사용하면 해당 브라우저의 저장 기록을 불러옵니다. 기록은 GitHub에 업로드되거나 기기 사이에서 자동 동기화되지 않습니다. 새 기기·새 브라우저에서는 JSON 백업을 가져오세요. 브라우저 데이터를 지우기 전에도 백업을 보관하세요.

## 개발 확인

별도의 의존성 설치나 빌드 없이 사용할 수 있습니다. Node.js 환경에서는 다음 명령으로 계산·데이터 모델 테스트를 실행합니다.

```sh
node --test logic.test.js model.test.js app-storage.test.js
```

이 테스트는 프로그램 계산과 데이터 처리를 확인합니다. 실제 기기의 화면 잠금 알림이나 GitHub Pages 배포 완료 여부를 검증하는 테스트는 아닙니다.
